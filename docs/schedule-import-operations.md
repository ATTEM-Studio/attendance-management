# 근무표 가져오기 운영 가이드

관리자 `근무 > 근무표`에서 **근무표 가져오기**를 사용합니다.

## 지원 형식

- Excel `.xlsx` 전용

Excel 파일은 브라우저에서 직접 분석하며 원본 파일은 서버에 저장하지 않습니다. 이미지, 사진, PDF 형식은 지원하지 않습니다.

## 기본 흐름

1. `.xlsx` 근무표 파일을 선택합니다.
2. 여러 시트와 영역 중 근무표 후보를 자동 탐지하고 가장 가능성이 높은 표를 추천합니다.
3. 대상 월과 `변경 적용 시작일`을 확인합니다.
4. 직원명을 기존 활성 직원과 자동 매칭합니다. 애매한 이름만 직접 선택합니다.
5. 기존 일정과 비교한 `신규 / 변경 / 삭제 / 보호 / 확인 필요`를 미리 확인합니다.
6. `변경사항 적용`을 누르면 서버가 현재 상태를 다시 확인한 뒤 한 번에 반영합니다.

## 수정본 업로드 규칙

수정본을 올린 날을 기본 적용 시작일로 사용합니다. 예를 들어 10월 15일에 수정본을 올리면 10월 1~14일은 바꾸지 않고 10월 15일 이후만 비교합니다. 시작일은 오늘보다 미래 날짜로 늦출 수 있지만 과거로 낮출 수 없습니다.

## 보호 규칙

실제 `clock_in` 또는 `clock_out` 기록이 있는 직원/날짜는 자동으로 수정하거나 삭제하지 않습니다. 미리보기 후 실제 적용 직전에 다시 검사하므로, 그 사이 직원이 출근해도 해당 일정은 보호됩니다.

## 전체표와 부분표

Excel에서 월~일 전체 범위와 시간축을 충분히 포함한 근무표로 판단된 경우에만 기존 일정의 삭제 후보를 만듭니다. 일부 직원이나 일부 요일만 포함된 표는 부분표로 취급하고 새 파일에서 보이지 않는 기존 근무를 삭제하지 않습니다.

## 동일 날짜 다중 근무

같은 직원에게 하루 두 구간 이상이 있으면 첫 구간은 기본 근무, 이후 구간은 추가 근무로 저장합니다. 겹치는 시간은 적용하지 않습니다.

## 장애 및 롤백

실제 반영은 PostgreSQL 함수 한 번의 트랜잭션으로 처리합니다. 중간 오류가 발생하면 전체 적용이 롤백되어 기존 일정이 유지됩니다. 가져오기 원본은 저장하지 않지만 `schedule_import_runs`에 적용 메타데이터와 변경 내역을 남깁니다.

문제가 생기면 해당 run의 `source_name`, `source_fingerprint`, `target_month`, `effective_date`, `applied_changes`를 확인하고 기존 날짜별 근무 편집 기능으로 수동 복구할 수 있습니다.
