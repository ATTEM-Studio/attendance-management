# 근무표 자동 가져오기 설계

## 1. 목적

기존에 Excel 또는 화면 캡처 이미지로 근무표를 관리하던 사용자가 기존 작업 방식을 버리지 않고도 근태관리 앱의 월간 근무 일정에 자동 반영할 수 있게 한다.

핵심 목표는 다음과 같다.

- `.xlsx` 파일에서 근무표 영역을 자동 탐지하고 직원/요일·날짜/근무시간을 추출한다.
- JPG/PNG 등 근무표 캡처 이미지에서도 같은 정규화 결과를 만든다.
- 앱에 등록된 직원과 자동 매칭한다.
- 기존 일정과 비교하여 신규/변경/삭제/확인 필요를 구분한다.
- 수정본 업로드 시 적용 기준일 이전의 과거 일정은 절대 변경하지 않는다.
- 이미 실제 출퇴근 기록이 발생한 일정은 자동 덮어쓰지 않는다.
- 적용 전 반드시 미리보기와 변경 요약을 제공한다.

## 2. 사용자 흐름

관리자 `근무` 화면에 `근무표 가져오기` 진입점을 추가한다.

1. `Excel 파일` 또는 `사진/캡처`를 선택한다.
2. 앱이 근무표 후보 영역을 분석한다.
3. 날짜가 없는 주간 패턴이면 적용할 연/월을 선택한다. 기본값은 현재 연/월이다.
4. `변경 적용 시작일`을 선택한다. 기본값은 업로드 당일이다.
5. 직원명 자동 매칭 결과를 확인한다.
6. 기존 근무표와 비교한 결과를 확인한다.
   - 신규
   - 시간 변경
   - 삭제
   - 변경 없음
   - 확인 필요
7. 관리자가 `변경사항 적용`을 누르면 안전 규칙을 다시 검증한 뒤 반영한다.
8. 적용 후 해당 월 데이터를 다시 불러오고 체크리스트를 재동기화한다.

## 3. 입력 형식

### Excel

지원 우선순위는 `.xlsx`이며 다음 요소를 함께 활용한다.

- 시트 이름
- 병합 셀
- 날짜/요일 헤더
- 좌측 시간축
- 셀 텍스트
- 숫자/시간 셀
- 배경색
- 반복되는 근무표 블록

급여표, 회의 메모, 주문 목록 등 근무 일정과 무관한 시트/영역은 근무표 후보 점수에서 제외한다.

근무표 후보가 여러 개면 가장 가능성이 높은 블록을 추천하되 사용자가 실제 적용할 블록을 선택할 수 있어야 한다.

### 이미지

JPG, PNG, WebP 캡처 이미지를 지원한다.

이미지는 단순 OCR 문자열만 사용하지 않고 다음 정보를 함께 해석한다.

- 표의 행/열 구조
- 요일 또는 날짜 열
- 시간축
- 색칠된 근무 블록 위치
- 블록 내부 직원명/시간 텍스트

이미지 분석은 서버 측 비전 분석 계층에서 처리하며 API 비밀키는 브라우저에 노출하지 않는다.

## 4. 정규화 모델

모든 입력은 다음 공통 구조로 변환한다.

```ts
type ImportedShift = {
  sourceRowId: string;
  employeeLabel: string;
  employeeId?: string;
  workDate: string;       // YYYY-MM-DD
  scheduledStart: string; // HH:mm
  scheduledEnd: string;   // HH:mm
  shiftType: 'open' | 'middle' | 'close' | 'open_middle' | 'middle_close' | 'other';
  confidence: number;     // 0..1
  notes?: string[];
};
```

날짜가 없는 `월~일` 반복형 시간표는 사용자가 선택한 대상 월의 실제 날짜로 펼친다. 적용 기준일 이전 날짜는 펼친 결과에서 제외한다.

동일 직원/동일 날짜에 두 개 이상의 근무 구간이 있으면 시작시간 순으로 정렬한다. 첫 구간은 `schedules`, 두 번째 이후 구간은 `extra_schedules`로 매핑한다.

## 5. 직원 자동 매칭

직원명은 현재 `employees` 테이블의 활성 직원과 비교한다.

매칭 순서:

1. 공백/직급/괄호 메모를 제거한 정확 일치
2. 일반적인 축약형 일치
3. 유사 문자열 후보 제시
4. 확신이 낮으면 자동 적용하지 않고 `확인 필요`

예: 파일의 `송이`와 등록 직원 `김송이`처럼 성이 생략된 경우 후보가 하나뿐이면 추천할 수 있지만 자동 확정 여부는 신뢰도 기준을 충족해야 한다.

한 번 사용자가 확정한 별칭 매핑은 이후 가져오기에서 재사용할 수 있도록 별도 매핑 데이터로 저장한다.

## 6. 적용 기준일 규칙

수정본 업로드의 기본 기준일은 업로드 당일(KST)이다.

예: 2026-10-15에 수정본 업로드

- 2026-10-01 ~ 2026-10-14: 변경 금지
- 2026-10-15 이후: 새 근무표와 기존 근무표 비교 가능

사용자는 필요할 경우 적용 시작일을 미래 날짜로 변경할 수 있다. 과거 날짜로 낮추는 것은 허용하지 않는다.

## 7. 변경 비교 규칙

비교 키는 기본적으로 `employee_id + work_date`이며 그 날짜의 모든 근무 구간을 하나의 집합으로 비교한다.

결과 상태:

- `add`: 기존에 없고 새 입력에 존재
- `update`: 직원/날짜는 같지만 시간 구간이 달라짐
- `remove`: 기존에는 있으나 새 입력의 권위 범위 안에는 없음
- `unchanged`: 동일
- `protected`: 실제 근태 기록 때문에 자동 변경 금지
- `needs_review`: 직원/시간/표 범위 해석이 모호함

삭제는 가장 위험하므로 입력이 해당 기간의 `전체 근무표`를 대표한다고 판정된 경우에만 자동 비교 대상으로 만든다. 잘린 캡처, 일부 직원만 포함된 표, 범위 판정이 불확실한 입력에서는 삭제를 자동 생성하지 않는다.

미리보기에서는 삭제 항목을 별도 강조하고 적용 전에 사용자가 볼 수 있어야 한다.

## 8. 실제 근태 보호 규칙

다음 조건 중 하나라도 만족하면 해당 직원/날짜의 계획 근무는 자동으로 변경하지 않는다.

- `attendance` 행이 존재하고 `clock_in`이 기록됨
- `attendance` 행에 `clock_out`이 기록됨
- 해당 날짜가 적용 기준일 이전

이 경우 변경 후보는 `protected`로 표시한다.

적용 API에서도 동일 조건을 다시 조회하여 UI 미리보기 이후 출근이 발생한 경쟁 조건을 막는다.

보호된 일정은 관리자 수동 근태/일정 수정 기능을 통해서만 처리한다.

## 9. 기본 근무와 추가 근무

현재 앱 구조를 유지한다.

- 첫 번째 시간 구간 → `schedules`
- 두 번째 이후 시간 구간 → `extra_schedules`

한 직원의 동일 날짜 내 근무 구간이 서로 겹치면 적용하지 않고 `needs_review`로 분류한다.

기존 시간만 수정되는 경우 가능한 한 기존 `shift_type`을 유지한다. 완전히 새로 생성되는 구간은 잘못된 체크리스트 배정을 방지하기 위해 기본적으로 `other`를 사용한다. 자동 shift type 추론은 이번 범위의 필수 기능으로 두지 않는다.

## 10. 아키텍처

### 프론트엔드

신규 모듈을 분리한다.

- `schedule-import.js`: 업로드 플로우, Excel 파싱, 정규화, 직원 매칭, 미리보기 UI
- `styles-schedule-import.css`: 가져오기 UI
- 빌드 단계에서 두 파일을 `dist`와 서비스워커 셸에 포함

Excel은 브라우저에서 구조적으로 파싱하여 서버에 원본 파일을 보낼 필요가 없게 한다.

이미지만 서버의 분석 엔드포인트로 전송한다.

### Supabase Edge Function

신규 `attendance-schedule-import` 함수를 추가한다.

역할:

- 관리자 세션 검증
- 이미지 비전 분석 요청
- 서버 기준 직원/기존 스케줄/근태 보호 상태 검증
- preview용 diff 생성 또는 검증
- apply 요청 처리
- 적용 후 체크리스트 동기화

이미지 분석 공급자는 서버 측 어댑터로 격리한다. 브라우저 코드에 모델 API 키를 포함하지 않는다.

### DB 적용

부분 실패를 피하기 위해 실제 변경 반영은 하나의 PostgreSQL 트랜잭션 경계 안에서 수행한다.

신규 DB 함수는 정규화된 근무 구간과 적용 기준일을 받아 다음을 수행한다.

1. 기준일/근태 보호 조건 재검증
2. 권위 범위 내 기존 `schedules`/`extra_schedules` 비교
3. 보호되지 않은 신규/수정/삭제 반영
4. 충돌 발생 시 전체 롤백
5. 적용 결과 반환

DB 함수는 일반 브라우저에서 직접 실행할 수 없게 하고 service-role 경로만 허용한다.

## 11. 가져오기 이력

원본 파일 자체는 기본적으로 서버에 장기 저장하지 않는다.

대신 `schedule_import_runs`에 다음 메타데이터를 기록한다.

- id
- source_type (`xlsx` / `image`)
- source_name
- source_fingerprint
- target_month
- effective_date
- parsed_count
- add_count
- update_count
- remove_count
- protected_count
- review_count
- status (`previewed` / `applied` / `failed`)
- applied_changes JSONB
- created_at / applied_at

이력은 문제 발생 시 어떤 가져오기가 어떤 일정을 바꿨는지 확인하기 위한 감사 용도다.

## 12. 미리보기 UX

상단 요약 예시:

- 신규 12
- 변경 5
- 삭제 2
- 확인 필요 1

목록은 날짜순으로 보여준다.

예:

`10/18 김송이 18:00~22:00 → 16:00~22:00`

`10/20 박시현 11:00~17:00 → 삭제`

`10/21 윤아 신규 08:00~11:00`

`10/22 세영 실제 출근 기록 있음 → 자동 변경 제외`

확인이 필요한 직원명은 드롭다운으로 앱 직원과 직접 연결할 수 있게 한다.

## 13. Excel 후보 탐지

근무표 후보 점수에는 다음 신호를 사용한다.

가점:

- 월~일 또는 실제 날짜가 연속된 열
- 08:00, 09:00 등 시간축
- 직원명과 시간 형식이 반복
- 색상 블록이 시간행을 따라 배치

감점:

- 급여/합계/시급/금액 중심 표
- 장문의 회의 메모
- 주문/발주 품목 중심 영역

후보가 여러 개면 `추천` 표시를 하되 자동 적용하지 않는다.

## 14. 이미지 해석 안전장치

이미지의 다음 항목은 신뢰도를 낮춘다.

- 잘린 요일 헤더
- 잘린 시간축
- 흐린 직원명
- 여러 셀이 겹친 이미지
- 일부 열만 캡처

낮은 신뢰도 항목은 삭제 판단에 사용하지 않는다.

이미지에서 시간 텍스트와 색칠 위치가 서로 다르면 둘 다 표시하고 `needs_review`로 보낸다.

## 15. 오류 처리

- 지원하지 않는 파일 → 즉시 형식 안내
- 근무표 후보 없음 → 다른 시트/범위/이미지 업로드 안내
- 직원 매칭 실패 → 적용 차단하지 않고 해당 행만 확인 필요
- 시간 역전/겹침 → 해당 행 적용 제외
- 서버 이미지 분석 실패 → Excel 기능에는 영향 없음
- DB 적용 실패 → 트랜잭션 전체 롤백 및 기존 일정 유지

## 16. 보안 및 개인정보

- 가져오기는 관리자 세션에서만 허용한다.
- Excel 원본은 기본적으로 브라우저에서 처리한다.
- 이미지는 분석에 필요한 동안만 서버/외부 비전 분석 계층으로 전달한다.
- 비전 API 키와 Supabase service role key는 브라우저에 노출하지 않는다.
- 파일 원본을 장기 보관하지 않는다.

## 17. 테스트 전략

### 파서 테스트

- 주간 패턴 Excel
- 날짜형 월간 Excel
- 급여/메모 시트가 함께 있는 Excel
- 동일 파일 내 근무표 블록 여러 개
- 직원명 축약/오타
- 동일 날짜 다중 근무

### diff 테스트

- 신규 배정
- 시간 변경
- 삭제
- 변경 없음
- 기준일 이전 변경 차단
- 출근 기록 있는 일정 보호
- 미리보기 후 출근이 발생한 경쟁 조건

### 적용 테스트

- base + extra 스케줄 교체
- 겹치는 시간 전체 롤백
- 체크리스트 재동기화
- 부분 실패가 없는지 검증

### 회귀 테스트

기존 수동 일정 추가/수정, 추가 근무, 출퇴근, 근태 수정 기능이 그대로 동작해야 한다.

## 18. 완료 기준

다음을 모두 만족하면 v1 완료로 본다.

1. 제공된 실제 Excel 샘플에서 근무표 영역을 찾고 직원/시간을 정상 추출한다.
2. 제공된 실제 캡처 이미지 형식에서 근무표를 정규화한다.
3. 수정본 업로드 시 적용 기준일 이전 일정이 변경되지 않는다.
4. 출근 기록이 있는 일정은 자동 변경되지 않는다.
5. 신규/변경/삭제/확인 필요를 적용 전에 확인할 수 있다.
6. 승인한 변경만 한 번에 반영되고 실패 시 기존 일정이 보존된다.
7. 한 날짜의 다중 근무가 기존 base/extra 구조에 맞게 저장된다.
8. 적용 후 체크리스트와 관리자 월간 화면이 정상 갱신된다.
9. 기존 근태 기능 회귀 테스트가 통과한다.

## 19. 이번 범위에서 제외

- AI가 직원 근무를 새로 추천하거나 자동 편성하는 기능
- 급여 계산 자동화
